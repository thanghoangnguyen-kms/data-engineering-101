# 👋 How to Use This Vault

**Back to:** [[00 - Onboarding Roadmap]]

> [!NOTE] Read This First
> This guide explains how to navigate and use the **Engineering 101** onboarding vault effectively. Spend 5 minutes here before starting your first domain.

---

## 🗺️ Where to Start

### 🖥️ Backend Track (B1 → B8)

1. Open **[[Backend/00 - Backend Track Roadmap|Backend Track Roadmap]]** — your progress tracker
2. Work through domains **B1 → B8** in order
3. Complete the **Checkpoint** at the end of each domain before moving to the next

### 🗄️ Data Engineering Track (D1 → D6)

1. Open **[[DataEngineering/00 - DE Track Roadmap|DE Track Roadmap]]** — your progress tracker
2. Work through domains **D1 → D6** in order
3. Complete the **Checkpoint** at the end of each domain before moving to the next
4. Domain **D7** is optional — tackle it after D6 if you're supporting AI/LLM workloads

> [!TIP] Shared foundations
> The tracks share Python, Git, and Linux basics. If you've completed the Backend track, you can skim D1 — most of it will be familiar.

---

## 📋 Tracking Your Progress

Each domain note has a `status` field in its frontmatter. Update it as you go:

| Status | Meaning |
|--------|---------|
| `not-started` | Haven't begun yet |
| `in-progress` | Currently working through it |
| `complete` | Content consumed, ready for checkpoint |

**To update:** Edit the frontmatter `status:` field in any note.

Each domain also has a `## ✅ Practice Checklist` — check off items as you complete them.

---

## ✅ How Checkpoints Work

1. Complete all practice checklist items in the domain note
2. Open the checkpoint note (e.g., `[[Backend/Checkpoints/CB1 - Dev Environment Ready]]` or `[[DataEngineering/Checkpoints/CP1 - Tooling & Environment Ready]]`)
3. Self-assess against each criterion — check the boxes you can honestly tick
4. **Book a review with your mentor** — they verify and sign off
5. Only after mentor sign-off: update checkpoint `status: complete` and move to the next domain

> [!WARNING] Don't Skip Checkpoints
> Checkpoints gate progression for a reason. If you can't pass CB3 database criteria, B4+ content won't stick. If you can't pass CP2 SQL criteria, D3+ content won't stick.

## 📚 How Notes Are Structured

Every domain note (B1–B8 and D1–D6) follows the same pattern:

```
[!NOTE] callout       ← What you'll learn
## N.M — Subdomain    ← Content sections
## ✅ Practice Checklist
## 📚 Domain References
## 🃏 Quick-Reference Flash Cards
Checkpoint link + navigation
```

## 🆘 Getting Help

- **Stuck on a concept?** Check the `## 📚 Domain References` section in the relevant domain note
- **Ready for checkpoint review?** Contact your onboarding mentor
- **Found an error or want to improve a note?** Flag it by setting `status: in-progress` in the frontmatter and noting the issue
